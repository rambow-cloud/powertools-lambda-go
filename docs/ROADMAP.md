# Implementation sequence

Post-v1 platform lifecycle requirements are assessed in the
[Managed Instances design](MANAGED_INSTANCES_DESIGN.md). Existing runtime
worker support is distinguished from project/platform acceptance.

Project requirements: prioritize native Go Lambda, keep CGO disabled, use local Docker by default, and favor cohesive packages with small dependencies. The legacy X-Ray SDK adapter is deprecated and frozen; maintained X-Ray support uses OpenTelemetry. Documentation and code comments remain English.

Complete a reviewable implementation slice with reference evidence before adding another package. Keep unfinished compatibility gates visible; a core implementation does not imply full parity. Performance, license review, release identity, and cross-package acceptance remain release requirements.

Use standard Go interfaces where sufficient. Metrics writes EMF through io.Writer and does not depend on Logger or Tracer. Parameters adapters share only cache/transform logic and default-provider lifecycle; service-specific requests remain in separate packages. Reuse primitives when demonstrated by multiple implementations rather than adding speculative frameworks.

Priority correction (2026-09-14): Commons is a shared foundation, not an end-stage utility. Existing modules already expose configuration/encoding inconsistencies, so consolidate their proven shared contracts before implementing more consumers. Metadata is a separate optional service client and must not become an unconditional dependency of ordinary logging, tracing, or parameter retrieval. Utility-specific defaults and cache policies remain with their owners.

Signer priority assessment (2026-09-14): no other pinned public package declares a Signer dependency, and Signer does not depend on Commons. Bring it forward for its bounded implementation and immediate IAM HTTP use cases; it does not unblock the remaining utilities. JMESPath remains the next shared dependency.

Module distribution (updated 2026-09-24): modules have independent dependencies and versions in one repository. HTTP, AppSync Events/GraphQL, Bedrock, Kafka with optional binary adapters, the shared optional regex module and the optional AWS Encryption SDK provider extend the layout to twenty-eight public modules and three development modules, with stable import paths and a shared workspace. See [MODULES.md](MODULES.md) and [PUBLISHING_PLAN.md](PUBLISHING_PLAN.md). Subsequent utilities should receive their own modules when implemented; the maintained cohort is publicly released at v0.2.0. See [v1 readiness](V1_READINESS.md) for the current release gates.
